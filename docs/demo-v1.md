# V1 เงินจำลอง รีวิว และการติดตาม

ฟีเจอร์ชุดนี้ใช้สำหรับสาธิตเท่านั้น ไม่ใช่ระบบรับชำระเงินจริง QR มีเพียงรหัสอ้างอิง
`LOCOMALL-DEMO-TOPUP:<uuid>` ซึ่งไม่ใช่ PromptPay และไม่มีข้อมูลบัญชีธนาคาร.
COD ยังคงทำงานเหมือนเดิม ออเดอร์ก่อน migration ได้ `payment_method='cod'` อัตโนมัติ.

## ติดตั้ง

1. สำรองฐานข้อมูลก่อน แล้วใช้ Supabase CLI/CI ตามขั้นตอน migration ของโครงการเพื่อใช้
   `supabase/migrations/20261004061208_demo_wallet_reviews_social_v1.sql`.
   อย่าคัดลอกบางส่วนไปรันแยก เพราะตาราง, RPC, RLS และ trigger ต้องติดตั้งพร้อมกัน.
   จากนั้นใช้ `supabase/migrations/20261004072602_demo_wallet_realtime.sql` เพื่อให้ยอดและ
   สถานะคำขอใน Wallet อัปเดตผ่าน Realtime เมื่อผู้ดูแลอนุมัติ (ยังตรวจ RLS ตามผู้ใช้).
2. ติดตั้ง dependency ด้วย `npm ci` แล้วสร้าง Development/Preview Build ใหม่ เพราะเพิ่ม
   `expo-crypto`, `react-native-svg` และ `react-native-qrcode-svg` (Expo Go ไม่ใช่เกณฑ์ทดสอบ APK).
3. ตรวจว่า `.env.local` มีเฉพาะ Supabase URL และ publishable/anon key; ห้ามใส่ service key ในแอป.

## ลำดับสาธิต

1. Buyer เปิด Profile → Wallet เงินจำลอง → ขอเติม 100 บาท. QR ที่ปรากฏใช้เป็นรหัสอ้างอิงเท่านั้น.
2. Admin เปิดศูนย์ควบคุม → ยอดเงินจำลอง → อนุมัติคำขอ. ผู้ใช้เพิ่มยอดให้ตนเองผ่าน Data API ไม่ได้.
   หาก Buyer เปิดหน้า Wallet ค้างไว้ ยอดและประวัติจะอัปเดตเอง; ดึงหน้าลงเพื่อรีเฟรชได้เมื่อเน็ตสะดุด.
3. Buyer เลือกใช้ยอดจำลองใน checkout. RPC เรียกการจองสต็อกเดิมแล้วหักยอดใน transaction เดียว;
   ถ้ายอดหรือสต็อกไม่พอ ออเดอร์/การจอง/การหักทั้งหมด rollback.
4. ยกเลิกออเดอร์ที่ยังยกเลิกได้เพื่อดูยอดคืนครั้งเดียว หรือให้ผู้ขายและเจ้าของตลาดดำเนินการ
   จน Buyer ยืนยันรับสินค้า. จากนั้นยอดตาม allocation จะเป็นยอดขายรอโอนของผู้ขาย.
5. Admin บันทึกโอนในเชิงสาธิตพร้อมหมายเหตุหลักฐาน. ไม่มีการโอนธนาคารเกิดขึ้น.
6. Buyer ให้คะแนนตลาดหนึ่งครั้งต่อออเดอร์ และร้านตามรายการที่ซื้อจริงหลังรับสินค้า;
   เจ้าของรีวิวแก้ไขได้ Admin ซ่อนรีวิวพร้อมเหตุผลได้.
7. บันทึกตลาด/ร้านไว้ดูภายหลัง หรือติดตามเพื่อรับข่าวร้านใหม่ที่อนุมัติและสินค้า
   กลับมาพร้อมขาย. ระบบแชร์พักไว้ก่อน.

## ทดสอบก่อนส่ง APK

- Buyer สองบัญชีและ Admin อีกบัญชี: อ่านยอด, ledger, คำขอ หรือรีวิวที่ซ่อนของคนอื่นไม่ได้.
- ส่ง top-up UUID เดิมซ้ำ: มีคำขอเดียว; Admin อนุมัติซ้ำต้องถูกปฏิเสธและยอดเพิ่มครั้งเดียว.
- สั่งซื้อพร้อมกันเมื่อยอด/สต็อกพอดี: สำเร็จได้เฉพาะรายการที่มียอดและสต็อกจริง;
  ยอด, reserved_quantity และ stock_quantity ไม่ติดลบ.
- ส่ง order request UUID เดิมซ้ำ: ได้ order_id เดิมและไม่หักยอดซ้ำ; UUID เดิมแต่ payload ต่างกันถูกปฏิเสธ.
- ยกเลิกซ้ำ/ยืนยันรับสินค้าซ้ำ: คืนยอดหรือเพิ่มยอดขายผู้ขายได้ครั้งเดียว.
- COD เดิมและออเดอร์เก่ายังเปิดได้; status การชำระของ COD ไม่เปลี่ยน.
- รีวิวก่อนรับสินค้า, ออเดอร์คนอื่น, รายการที่ไม่ได้ซื้อ ถูกปฏิเสธ; คะแนนที่ซ่อนหลุดจากค่าเฉลี่ย.
- Favorite/Follow ซ้ำไม่สร้างแถวเพิ่ม; ตลาด/ร้าน pending หรือ suspended ต้องไม่แสดงในรายการที่บันทึก.
- ตรวจป้าย “เงินจำลอง” ทุกหน้าที่เกี่ยวข้อง.

`npm test`, `npm run typecheck` และ `npm run lint` ตรวจ static contract/UI; **ไม่แทน**
concurrent database test และการทดสอบกับ APK จริงบนหลายบัญชี.

## รีเซ็ตข้อมูลทดสอบ

ใช้ฐานข้อมูล local/test ที่แยกจากงานจริงเท่านั้น: หยุดแอปแล้วรัน `npx supabase db reset`
เพื่อสร้างใหม่จาก migration และ seed (คำสั่งนี้ลบข้อมูลทั้งฐาน local/test).
อย่าลบ `demo_ledger` บางแถวหรือแก้ `demo_accounts` ด้วยมือในฐานข้อมูลที่ใช้ร่วมกัน
เพราะจะทำลาย audit trail; ถ้าต้องเริ่มรอบสาธิตใหม่ให้ใช้ test project/branch ใหม่.

## ก่อนรับเงินจริงในอนาคต

ต้องเลือกผู้ให้บริการรับชำระที่รองรับบัญชีธุรกิจ, ออกแบบ webhook ที่ตรวจลายเซ็น,
กระทบยอด, refund, payout, dispute, ภาษี/กฎหมายและการดูแลข้อมูลส่วนบุคคลใหม่ทั้งชุด.
ห้ามเพียงเปลี่ยน QR/ป้ายจาก “จำลอง” เป็น “เงินจริง”.
