# Stripe Sandbox สำหรับ Locomall

รุ่นนี้รองรับเฉพาะคีย์ `sk_test_` และตรวจ `livemode=false` ห้ามนำไปเปิดรับเงินจริง
หรือใช้แทนระบบแบ่งจ่ายเงินจริงให้ผู้ขาย Wallet เดิมยังเป็นยอดจำลองแยกจาก Stripe

## สิ่งที่ติดตั้ง

- `stripe-checkout`: ตรวจ session ผู้ใช้ สร้างออเดอร์/จองสต็อกและ Checkout Session โดยคำนวณยอดจากฐานข้อมูล
- `stripe-webhook`: ตรวจ HMAC จาก raw body และเวลา ไม่ใช้ JWT ของแอป; อ่านสถานะล่าสุดจาก Stripe อีกครั้ง
- `stripe-return`: redirect กลับ `locomall://order/<id>` โดยไม่ยืนยันผลจาก redirect
- Private payment table และ RPC ที่ให้เฉพาะ service role; app อ่าน/เปลี่ยนสถานะการชำระตรง ๆ ไม่ได้
- ตรวจสถานะซ้ำทุกนาทีผ่าน Cron เพื่อปิด session ที่ยกเลิก ปลดจองเมื่อ Stripe ยืนยันว่าหมดอายุ และติดตามคืนเงิน
- คีย์ Stripe/Webhook/Worker อยู่ใน Supabase Secrets; worker token แยกจาก service key และเก็บใน Vault สำหรับ Cron
- ไม่เปิดรับงานผู้ขายก่อนจ่ายสำเร็จ และแจ้งออเดอร์ใหม่เมื่อยืนยันการชำระครั้งแรกเท่านั้น

## ทดสอบผ่าน APK

1. เลือกสินค้าจากตลาดเดียว ยอดตั้งแต่ 10 บาท เลือกที่อยู่หรือนัดรับตามสิทธิ์เดิม
2. เลือก “Stripe · โหมดทดสอบ” แล้วสร้างออเดอร์ ระบบจองสต็อกแต่ยังไม่ตัดสต็อกจริง
3. เปิดหน้าชำระจากออเดอร์ ใช้ข้อมูลทดสอบเท่านั้น ห้ามใช้บัตรหรือแอปธนาคารจริง
4. บัตรสำเร็จใช้ `4242 4242 4242 4242` วันหมดอายุในอนาคตและ CVC ทดสอบ ดูกรณีอื่นจาก [Stripe testing](https://docs.stripe.com/testing)
5. สำหรับ PromptPay ใช้ตัวจำลองการทดสอบที่ Stripe แสดง ไม่สแกนจ่ายเงินจริง
6. เมื่อกลับแอป ระบบตรวจสถานะอีกครั้ง; หากเปิดแอปอัตโนมัติไม่ได้ ให้ปิดเบราว์เซอร์แล้วเปิดออเดอร์เดิม
7. ตรวจผู้ขายได้รับแจ้งครั้งเดียว เริ่มเตรียมได้หลังจ่าย และการรับที่จุดรวม/ตัดสต็อกยังเป็น flow เดิม
8. ทดสอบยกเลิกก่อนจ่าย, จ่ายแล้วก่อนส่งมอบ, ปิดแอประหว่างจ่าย, เน็ตหลุด, รีเฟรชซ้ำ และรอ session หมดอายุประมาณหนึ่งชั่วโมง
9. กรณีชำระชนกับยกเลิกต้องไม่เปิดงานผู้ขาย ต้องแสดงรอคืนเงินจน Stripe ยืนยันคืนสำเร็จจริง

## Diagnostics

`node scripts/check-stripe-sandbox.mjs` ตรวจ endpoint, worker และ native return โดยไม่แสดงคีย์
เพิ่ม `--provider-event` เพื่อสร้าง/ปิด session ทดสอบที่ไม่ผูกออเดอร์ และตรวจ event delivery จริง
การตรวจนี้ไม่ใช่การชำระออเดอร์ในแอปครบวงจร

## ข้อจำกัดที่ต้องทราบ

- รองรับบัตร/PromptPay ตามการตั้งค่า Sandbox; ยังไม่ใช่ Stripe Connect seller payouts หรือ escrow
- คืนเงินผ่านช่องทางเดิมใน Stripe ไม่เพิ่มยอดเข้า Wallet จำลอง และไม่แบ่งยอด Stripe ลง demo ledger
- คืนเงินที่ pending/failed ต้องติดตามต่อ ไม่แสดงว่าสำเร็จเอง กรณีที่ต้องดำเนินการใน Dashboard ให้ผู้ดูแลตรวจสอบ
- รอบนี้รองรับคืนเงินจากการยกเลิกใน Locomall เท่านั้น การคืนเงินเองจาก Stripe Dashboard/คืนบางส่วนยังไม่ sync กลับอัตโนมัติ ต้องตรวจและกระทบยอดด้วยผู้ดูแลก่อนดำเนินออเดอร์ต่อ
- หาก Stripe ล่ม ไม่ปล่อยสต็อกตามนาฬิกาเพียงอย่างเดียว เพราะอาจมีการจ่ายสำเร็จที่ยังไม่ได้รับ event
- หากสร้าง session ไม่สำเร็จเป็นเวลานาน ต้องตรวจออเดอร์เดิมก่อนเริ่มสั่งใหม่ อย่าล้างประวัติชำระเพื่อแก้ปัญหา
- APK เก่าจะไม่มี UI Stripe ให้ใช้ APK รุ่นที่รวมงานนี้ บัญชีที่มีบทบาทอื่นยังต้องถูกตรวจสิทธิ์ตามเดิม
- Test secret key ไม่ใช่ live key; `charges_enabled` ของบัญชีไม่ใช่หลักฐานว่ารุ่นนี้พร้อมรับเงินจริง
